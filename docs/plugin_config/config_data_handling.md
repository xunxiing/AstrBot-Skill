## 概述

本文档描述 AstrBot 在处理插件配置（Plugin Config）时的自动化数据清洗与同步逻辑。为了确保插件开发者在读取配置时获得一致且符合预期的 Python 数据类型，系统在 WebUI 渲染层（Dashboard）与后端存储层之间建立了严格的数据校验与过滤机制。

## 核心逻辑：列表项清洗 (List Sanitization)

在处理 `type: "list"` 或 `type: "template_list"` 的配置项时，AstrBot 遵循以下自动化清洗规则：

1. **空值归一化**：
   - 当用户在 WebUI 中删除所有列表项，或仅留下空白字符时，系统会将该配置项强制归一化为 `[]` (空数组)，而非 `[""]` (包含空字符串的数组)。
   - 这一逻辑在 `ListConfigItem.vue` 组件的 `singleItemValue` setter 和 `confirmDialog` 提交阶段触发。

2. **实时过滤 (Reactive Filtering)**：
   - 系统通过 `watch` 监听 `modelValue` 的变化。若检测到数组中存在仅包含空白字符的字符串项，将自动执行过滤并触发 `update:modelValue` 事件。
   - 使用 `nextTick` 确保 UI 状态与父组件数据流同步，防止因异步更新导致的脏数据写入。

3. **类型安全检查**：
   - 在清洗过程中，系统会检查列表项的原始类型。仅对 `string` 类型执行 `.trim() !== ''` 检查，保留非字符串类型（如 `object` 或 `number`）的合法性，确保 `template_list` 等复杂结构的完整性。

## 数据流向

1. **UI 输入**：用户通过 `ListConfigItem` 组件编辑列表。
2. **前端清洗**：组件内部过滤空字符串，将无效输入转换为标准空状态。
3. **配置保存**：清洗后的数据通过 `ExtensionPage` 提交至后端，不再需要二次过滤。
4. **插件读取**：插件通过 `self.config` 获取到的列表保证不含无效空元素，降低了业务逻辑中 `if item:` 判空的负担。

## 变更影响分析

- **对 AI 消费者的影响**：在编写处理配置列表的插件逻辑时，AI 可以安全地假设 `list` 类型的配置项要么是包含有效内容的数组，要么是完全空的数组 `[]`。无需额外编写复杂的正则或字符串过滤逻辑来处理 `[""]` 这种边界情况。
- **边界情况**：如果插件确实需要存储空字符串作为合法配置值（极少见），此机制会将其拦截。目前设计倾向于数据整洁性而非保留空字符串。
- **最佳实践**：开发者在 `_conf_schema.json` 中定义 `list` 类型时，应预期获取到的数据已完成 `trim` 处理。建议在插件逻辑中直接迭代列表，无需担心空字符串导致的逻辑异常。
